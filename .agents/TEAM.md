# 공통 작업 규칙

도구의 비공개 대화 기록은 공유되지 않는다. 이 폴더의 기록과 실제 Git diff가 인수인계 기준이다.

## 역할
- frontend: UI·디자인 토큰·접근성·반응형. 기본 실행 도구는 Claude Code.
- backend: API·데이터·시스템 로직·테스트. 기본 실행 도구는 Codex.
- review: 요구사항·통합 검토·QA. 기본 실행 도구는 Antigravity.
- lead: 목표·API 계약·파일 담당·작업 순서. 도구 제한 없음.
도구와 역할은 독립적이다. 사용자가 지정한 역할이 항상 우선한다.

## 시작·전환·완료
1. 작업 시작과 매 사용자 요청에서 HANDOFF.md, TEAM.md, 해당 역할을 포함한 notes/*.md, 실제 git status/diff를 확인한다. 외부 서버 fetch는 필요하지 않다.
2. 수정 전 자신의 notes/<role>.md에 목표·담당 파일·작업 중 상태를 적는다. 다른 역할이 소유 중인 파일은 수정하지 않고 먼저 인계한다. 이는 협업 규칙이며 OS 파일 잠금은 아니다.
3. 같은 역할을 두 세션에서 동시에 실행해 같은 메모/파일을 수정하지 않는다. 병렬 작업이 필요하면 사용자 범위에 맞는 별도 worktree 또는 명확히 나뉜 파일 담당을 사용한다.
4. 단계 완료, 오류/중단, 최종 응답 직전에 자신의 메모에 변경 파일, 결정 이유, 실행 명령과 결과, 미검증 항목, 다음 행동을 기록한다. 테스트 성공을 추정하지 않는다.
5. 코드 수정이 없고 새 결정도 없는 간단한 대화에서는 불필요한 파일을 만들거나 검증하지 않는다. 기존 메모를 읽지 않고 덮어쓰지 않는다.
6. HANDOFF.md는 lead 또는 사용자가 지정한 단일 담당자만 갱신한다. 다른 역할은 자기 메모로 인계한다. lead가 없으면 현재 작업자가 다른 세션의 수정 여부를 확인하고 갱신한다.
7. 기록은 프로젝트 안에만 저장한다. 비밀번호, 토큰, 원본 대화 전문, 개인 데이터를 넣지 않는다. 외부 자동 업로드·자동 commit·push는 하지 않는다.
8. 완료 이벤트가 .agents/auto/LATEST.md와 history/에 최근 요청·완료 응답·변경 경로를 자동 저장한다. 별도 저장 요청은 필요 없다. 새 세션은 이 자동 기록도 읽는다. 정상 완료 이벤트 전 강제 종료/전원 차단의 미완료 내용은 저장을 보장하지 않는다.

계획/읽기 전용 모드에서 에이전트는 권한을 넘어 메모를 쓰지 않는다. 사용자가 승인한 로컬 완료 hook은 작업 응답의 자동 기록만 저장한다.

각 프로젝트의 실제 기술 스택과 검증 명령은 루트 지침을 따른다. 역할을 바꾼다고 라이브러리나 프레임워크를 새로 도입하지 않는다.
