# 디자인 결정 기록

온기산후(산후 회복 셀프케어 앱)의 화면 디자인을 왜 이렇게 정했는지 적은 문서입니다.
색·글꼴 값의 실제 정의는 `src/app/globals.css`의 `@theme` 블록 한 곳에 있습니다.

## 방향

산모가 아기를 재우고 한 손으로 여는 앱입니다. 병원 앱처럼 차갑지 않고, 흔한 서비스 템플릿처럼 보이지도 않아야 합니다.
그래서 색과 구조를 한국의 산후조리 문화에서 가져왔습니다.

| 요소 | 출처 | 쓰임 |
| --- | --- | --- |
| 살구빛 바탕 `--color-bg` | 조리원의 따뜻한 조명, 한지 | 화면 배경 |
| 대추색 `--color-primary` | 산후에 달여 마시는 대추차 | 주 버튼, 강조, 진행 표시 |
| 쑥색 `--color-sage` | 쑥 찜질·좌욕 | 완료 표시, 삼칠일 구간 |
| 백일 점 달력 | 삼칠일(21일)과 백일(100일) 풍습 | 첫 화면의 주인공 |

## 이 앱만의 요소: 백일 점 달력

출산 후 100일을 점 100개(10×10)로 보여줍니다. 지난 날은 채워지고, 삼칠일까지는 쑥색, 그 뒤는 대추색입니다.
21일째와 100일째 점은 비어 있을 때도 테두리로 표시됩니다. 오늘은 바깥 테두리로 표시됩니다.
"지금 회복의 어디쯤인지"를 숫자 대신 한눈에 보여주는 것이 목적입니다. 앱 아이콘도 이 점에서 가져왔습니다.

## 글꼴

- 제목: Gowun Dodum (둥글고 손글씨 느낌이 살짝 있는 고딕). 클래스 `display`
- 본문: 기기 기본 한글 고딕 (Pretendard가 있으면 우선)
- 본문 16px 이상, 줄 간격 1.6, 단어 단위 줄바꿈(`word-break: keep-all`)

## 규칙

- 색은 토큰 클래스(`bg-primary`, `text-muted` 등)로만 씁니다. 컴포넌트에 hex 값을 직접 쓰지 않습니다.
  예외는 CSS 변수를 쓸 수 없는 두 곳입니다: `src/lib/theme.ts`(매니페스트·브라우저 테마색), `public/icon*.svg`.
- 간격은 4px/8px 단위.
- 누를 수 있는 것은 높이 44px 이상, 서로 8px 이상 띄웁니다.
- 모든 버튼·입력·선택지에 hover, 키보드 focus(3px 대추색 테두리), disabled 상태가 있습니다.
- 그림자를 쓰지 않습니다. 구분은 옅은 색 면과 얇은 선으로 합니다.
- 아이콘은 직접 그린 SVG(`src/components/icons.tsx`)만 쓰고 이모지는 쓰지 않습니다.
- 움직임은 사용자의 행동에 답할 때만 씁니다. 자동 애니메이션은 오늘 점이 나타나는 한 번뿐입니다.
  `prefers-reduced-motion` 설정을 따릅니다.
- 화면은 휴대폰 폭(최대 480px)의 한 단입니다. 넓은 화면에서는 가운데에 놓입니다.

## 검증 과정

### 1. 디자인 스킬 검토 (2026-11-23)

- `frontend-design`: "크림 배경 + 세리프 제목 + 테라코타 강조"는 AI가 만든 화면에서 가장 흔한 조합이라고 지목합니다.
  처음 구상이 정확히 이 조합이어서 버리고, 위의 산후조리 팔레트와 둥근 고딕으로 바꿨습니다.
  같은 이유로 영문 대문자 라벨, 가운뎃점으로 이은 메타 정보, 버튼 끝의 화살표, 똑같은 그림자 카드 반복을 쓰지 않습니다.
- `ui-ux-pro-max`: 접근성 규칙(대비 4.5:1, 44px 터치 영역, 입력 라벨, reduced-motion, 이모지 아이콘 금지)을 채택했습니다.
  추천 팔레트는 병원풍 청록이어서 "따뜻하게"라는 요구와 맞지 않아 채택하지 않았습니다.

### 2. Google Stitch 시안 (2026-11-23)

같은 팔레트와 화면 구성을 Stitch에 넣어 시안 4장(오늘, 온보딩, 운동 상세, 코치)을 받아 비교했습니다.
프로젝트 이름은 "Korean Postpartum Recovery Coach"이며 요청한 계정의 Stitch에 남아 있습니다.

채택한 것
- 살구빛 바탕 위 대추색·쑥색 조합 (실제 화면에서 따뜻하고 글자가 잘 읽힘)
- 백일 점 달력을 첫 화면 맨 위에 크게
- 삼칠일까지와 이후를 색으로 구분
- 분만 방식은 큰 선택지 두 개
- 설문 상단의 진행 막대

버린 것
- 카드 안에 카드를 넣는 구조
- 선택지마다 붙은 태그 칩과 "권장 케어" 배지 (읽을 것이 너무 많아짐)
- 영문 라벨(Today, Coach), 알림 종 아이콘 (기능이 없음)
- 코치의 가짜 프로필 사진
- "전문 물리치료사 검수" 문구 (사실이 아님. 감수 전까지 넣지 않습니다)

### 3. 실제 화면 확인

구현 후 모바일 폭으로 띄워 스크린샷으로 확인하고 고친 내용은 아래에 이어서 적습니다.

2026-11-23, 컴퓨터 브라우저에서 휴대폰 폭(500px)과 넓은 화면(1280px)으로 6개 화면을 모두 확인했습니다.

- 오늘 화면의 백일 점 달력이 작아 주인공 역할을 못 해 152px에서 168px로 키웠습니다.
- 넓은 화면에서 가운데 한 단만 있어 허전했습니다. 휴대폰 모양의 둥근 틀 안에서 스크롤되게 하고,
  화면이 더 넓으면(1024px 이상) 왼쪽에 앱 소개를 붙였습니다. 휴대폰에서는 전체 화면 그대로입니다.
- 설문에서 답을 고르지 않고 "다음"을 누르면 버튼 바로 위에 무엇을 해야 하는지 나옵니다.
- 코치 화면에서 AI 연결이 없어도 위험 증상 안내는 말풍선으로 먼저 나오는 것을 확인했습니다.

아직 확인하지 않은 것: 실제 안드로이드·아이폰 기기, 글꼴 크기를 키운 접근성 설정, 화면 낭독기.

### 4. iOS 시뮬레이터 확인 (2026-11-23, iPhone 17e / iOS 27.0)

시뮬레이터에서 6개 화면을 모두 열어 보고 고친 것들입니다.

- **출산일 입력칸이 화면 밖으로 삐져나갔습니다.** 컴퓨터 브라우저에서는 안 보이고 iOS에서만 나타난 문제입니다.
  원인은 `fieldset`의 기본 최소 폭이 안쪽 내용물 폭이라는 점이었고, `fieldset { min-width: 0 }`로 해결했습니다.
- 안전 영역(상태 표시줄) 아래에 여백이 겹쳐 화면 위쪽이 너무 비어 보였습니다. 화면 위 여백을 32px에서 16px로 줄였습니다.
- 첫 화면에서 버튼 아래 안내 문구가 잘렸습니다. 제목 크기와 점 달력 크기, 여백을 줄여 한 화면에 들어오게 했습니다.
- 오늘 화면: 목록 맨 아래에 있던 시작 버튼을 목록 위로 올렸습니다. "시작하기: 횡격막 호흡"처럼 다음 운동 이름이 보입니다.
- 운동 상세: 화면 맨 아래에 "오늘 했어요" 버튼을 추가했습니다. 오늘 화면의 체크와 같은 기록을 씁니다.
- 로딩·오류: 화면 이동 중 뼈대(`loading.tsx`), 오류 화면(`error.tsx`), 코치 답변 대기 중 점 세 개, iOS 앱의 첫 로딩 화면을 추가했습니다.
- 개발용 Next 표시("N" 동그라미)가 하단 탭을 가려서 개발 중에도 숨겼습니다.

아직 못 본 것: 코치 답변이 오는 동안의 점 세 개 모양(스크린샷으로 잡지 못함), 홈 화면 아이콘 모양, 실제 기기.
